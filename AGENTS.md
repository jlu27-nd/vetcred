# VetCred development instructions

- Verify `origin` is `jlu27-nd/vetcred` before repository operations. Work on a feature branch; preserve user changes. Preview team/project: `jon-lu-llc` / `vetcred`; root directory is this repository root. Do not promote production as part of a preview task.
- Use Node.js 24, pnpm 11.25.0 and the pinned lockfile. Run `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` after meaningful changes. Read installed Next.js and AI SDK documentation before using APIs that may have changed.
- Read the installed Supabase skill when available. Create migrations with `supabase migration new`; do not rewrite applied files. Use only an isolated preview database for migrations/seeding/tests. `VETCRED_PREVIEW_PROJECT_REF` is mandatory for those scripts and must match the configured project.
- Never print, commit or expose secrets, source documents or transcripts in logs. `.env.local`, `.vercel/`, `work/`, test traces and local account credentials are ignored. Only publishable Supabase configuration may use `NEXT_PUBLIC_`.
- All tenant records require organization/case ownership, RLS and same-case references. Verify identity server-side. Elevate a transaction only after its case and actor are authorized; error handlers require the same checks. Browser roles/organization IDs and JWT user_metadata are never authorization evidence.
- Preserve originals and accepted user edits. New generation is a proposal with versioned prompts and validated authorized source IDs. Never let uploaded instructions become system instructions or authorize tools, publishing or approval.
- Keep review status separate from evidence status. A military occupation suggests questions; it does not establish an individual's tasks or credentials. Do not invent metrics, outcomes, qualifications or verification badges.
- Keep both Storage buckets private. Authorize direct uploads before processing and validate actual bytes after upload. Only metadata-stripped, explicitly selected derivatives can be published. Public response DTOs must exclude raw originals, transcripts, source links and internal feedback.
- Require veteran approval of the exact current revision before publishing. Never mutate a published snapshot. Share-token checks apply to both page and media routes; revoke them together.
- Maintain the labeled fixture mode separately from live processing. Never respond to arbitrary uploads with canned output while implying real provider execution. Sample reset retires the prior session and revokes links; it is not physical deletion.
- Use `VETCRED_RUN_DB_TESTS=1` and `VETCRED_RUN_LIVE_E2E=1` only with explicitly selected preview configuration. Provider journey tests spend credits and create isolated accounts. Keep all service secrets out of untrusted PR jobs. Distinguish mocked tests, real database tests and real-provider/deployed-preview evidence in handoffs.
- Prefer accessible controls, visible focus, labeled fields, meaningful loading/error/retry states and plain professional language. Keep scope on photo stories, resume translation, guided voice stories and the approved portfolio journey.
